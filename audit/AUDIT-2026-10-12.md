## Bloqueos antes de publicar

**A01 — P1: Supabase real sigue exigiendo apellido.** La consulta del esquema confirmó `leaderboard_last_name_check` con longitud entre 1 y 60; el servidor nuevo envía `last_name = ''` cuando se escribe solo un nombre. Por tanto, ese guardado fallará en producción aunque pase en el entorno temporal. `run_id` y su índice único sí están presentes. Este hallazgo se corrigió posteriormente con una migración que consolida los nombres en una sola columna y conserva RLS; ver el seguimiento de Supabase al final.

**A02 — P1 para una competencia con premios: el ticket no verifica la partida.** En un servidor aislado se solicitó un ticket válido, se avanzó el reloj de prueba 12 segundos y se enviaron 15.000 puntos y oleada 8, sin ejecutar la simulación. La API devolvió **201** e insertó el resultado. El HMAC protege el ticket y el tiempo, pero `score` y `wave` siguen siendo declaraciones del navegador. Las cotas generosas no son prueba de legitimidad. Para un ranking con premios, validar una simulación autoritativa o un registro verificable de entradas; entretanto, tratar este ranking como casual. Evidencia: [server.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/server.js:132).

**A03 — P1: una pantalla horizontal pequeña provoca Game Over inmediato.** En el navegador, 740×360 deja un mundo Canvas de 600×144. La física real genera enemigos con borde inferior Y=73 mientras la hitbox del jugador empieza en Y=65. Las oleadas 3, 4 y 7 terminan tras el primer paso de 1/120 s. El mínimo artificial `Math.max(1, ...)` oculta que no existe espacio vertical disponible. Proteger los tamaños insuficientes: mantener pausa hasta volver a retrato o garantizar un mundo mínimo y un layout que respete realmente la barrera. Añadir pruebas de rotación y pantallas horizontales. Evidencia: [Enemy.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/src/entities/Enemy.js:45) y [Game.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/src/Game.js:150).

**A04 — P1: un guardado confirmado por la base puede quedar bloqueado en el formulario.** Se simuló una respuesta perdida después de insertar. Al reintentar, el índice de `run_id` provoca 409 «Esta partida ya fue publicada». El cliente queda con `sent=false`, formulario abierto y ranking oculto; solo hizo dos POST y ningún GET. Implementar reintentos idempotentes para el mismo ticket y contenido, conservando el rechazo a resultados distintos, y permitir recuperar el resultado ya guardado. Conservar estado HTTP en los errores de la API para distinguir duplicado de fallo de conexión. Evidencia: [server.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/server.js:145) y [Leaderboard.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/src/Leaderboard.js:229).

**A05 — P1 operativo: el despliegue existente no tiene API de ranking.** Las peticiones de solo lectura a `https://cuyinvader.onrender.com/` devolvieron 200; `/api/health` y `/api/leaderboard` devolvieron **404**. Publicar solo el frontend en ese servicio no activa Express. Preparar el Web Service de [render.yaml](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/render.yaml:1), con `npm ci`, `npm start`, las variables reales de Supabase y un `GAME_SESSION_SECRET` aleatorio. Las variables locales de clave de servicio y secreto todavía parecen valores de ejemplo; no se incluyeron sus valores en esta auditoría. Verificar juego y API en el mismo origen después del despliegue.

## Correcciones de alto valor

**A06 — P2: no existe acceso a pantalla completa en móvil.** En 390×844, el navegador mostró cero botones visibles de Ampliar/Pantalla completa. Se eliminó el botón interno, pero los media queries mantienen `.hud .expand { display: none; }`. Hacer visible el botón superior en el HUD móvil y probar su solicitud de fullscreen. Evidencia: [style.css](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/style.css:195).

**A07 — P2: el misil no mantiene el área 3×3 en la formación triangular.** En oleada 8, 1200×800, una detonación central alcanzó 9 enemigos/3 filas en bloque y **20 enemigos/7 filas** en triángulo. La altura de explosión, 406 px, se calcula siempre con el número de filas del bloque. Derivar el paso vertical de la formación vigente o definir vecindades lógicas; cubrir bloque, triángulo y semiluna con pruebas del área generada por `activatePowerUp`. Evidencia: [Game.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/src/Game.js:323).

**A08 — P2: las cuotas por IP pueden bloquear participantes de una misma red.** La prueba emitió 20 sesiones desde una IP y la siguiente recibió 429. Las publicaciones además se limitan a cinco por minuto por IP. En un evento con Wi-Fi compartido, jugadores distintos consumen la misma cuota; si falla la sesión inicial, no hay reintento durante esa partida y Guardar queda deshabilitado. Ajustar cuotas para la asistencia prevista, combinar controles por sesión y por IP, y probar recuperación con `Retry-After`. El store actual es de memoria: la fábrica para Redis existe, pero no se configura almacenamiento compartido. Evidencia: [server.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/server.js:110) y [Game.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/src/Game.js:226).

**A09 — P2: el health check no confirma que el ranking funcione.** Con la base simulada caída, `/api/health` devolvió 200 y `/api/leaderboard` 503. Añadir una comprobación de readiness o una verificación separada de conexión/esquema en el despliegue. Registrar códigos de errores del servidor de forma sanitizada para distinguir credenciales, migración y caída de base. Evidencia: [server.js](C:/Users/YORDAN-TUF/Desktop/YordanDeVp/CuyInvader/server.js:108).

**A10 — P2/P3: falta cerrar la preparación del repositorio.** `.env.example` no existe aunque el README indica copiarlo; el README aún describe el botón interno de fullscreen eliminado. No hay workflows de CI ni un procedimiento de rollback documentado. Servidor, lockfile, API, reglas compartidas y migraciones todavía están sin seguimiento de Git y deben incluirse en el commit de lanzamiento. Crear el ejemplo sin claves, actualizar instrucciones y ejecutar pruebas en CI. Los casos A03, A04 y A07 no están cubiertos por la suite actual.

## Seguimiento local de correcciones — 12 de octubre de 2026

- **A01, corregido y aplicado en Supabase.** El servidor y el cliente usan solo `name`. La migración `20261012213850_leaderboard_name_only.sql` consolida nombres históricos, renombra `first_name` y elimina `last_name`. El esquema remoto quedó verificado contra el payload del juego.
- **A02, mitigación temporal aplicada; sigue bloqueando premios.** El mínimo subió a 15 segundos iniciales más 15 por oleada (oleada 8: 120 segundos). El ticket HMAC sigue siendo del servidor. Una prueba sin ejecutar el juego confirma que, después de esperar el mínimo, todavía se pueden enviar puntos fabricados dentro de la cota. No colocar una clave compartida en JavaScript; hace falta simular/verificar la partida en el servidor.
- **A03, corregido para móvil horizontal.** La aplicación detecta la orientación, pausa la partida, oculta el canvas y muestra la pantalla para girar. Al volver a retrato queda en pausa y no reanuda sola.
- **A04, corregido.** Reintentar el mismo ticket con idénticos nombre, puntaje y oleada devuelve el registro guardado (`200`); cambiar el resultado se rechaza (`409`). El cliente solo abre el Top 10 tras `200/201`; `finally` restaura campo y botón si falla la petición.
- **A05, sigue pendiente en Render.** `render.yaml` y README describen el Web Service monolítico, comandos y variables. La URL del Static Site anterior seguirá respondiendo 404 en `/api/*` hasta crear el servicio Node y, si se desea, migrar el dominio.
- **A10, parcialmente corregido.** Se agregó `.env.example` sin credenciales y se actualizó la guía de despliegue. Falta integrar los archivos locales en Git y preparar CI/rollback.

La suite pasó **42/42 pruebas**. `node audit/probes.mjs` ahora muestra la pausa en paisaje, el rechazo de una oleada 8 enviada en 5 segundos, la falsificación que aún pasa al esperar 120 segundos y la recuperación del guardado perdido. Por eso los fixes de UX y reintento están listos localmente, pero el ranking continúa **no apto para premios** hasta validar el juego en servidor.
